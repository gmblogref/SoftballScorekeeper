# Contributing to Softball Scorekeeper

Contributions are welcome through pull requests, but submission does not
guarantee acceptance. Before starting substantial work, explain the proposed
change in an issue or other repository discussion so its scope can be reviewed.

## Workflow

1. Read `AGENTS.md` and `FEATURE_HISTORY.md` before changing the project.
2. Fork the repository, or use a feature branch when the repository owner has
   authorized branch access.
3. Keep the change focused and explain its purpose and behavior in the pull
   request.
4. Run the relevant tests and validation described by the repository. Report
   results and any validation that could not be completed accurately.
5. Submit a pull request for review. Changes to the authoritative `main` branch
   are controlled by the repository owner.

Never commit credentials, private information, local databases, signing
keystores or certificates, private keys, generated release artifacts, or
machine-specific configuration.

The project does not currently require a Contributor License Agreement or a
Developer Certificate of Origin sign-off. Third-party material must retain its
